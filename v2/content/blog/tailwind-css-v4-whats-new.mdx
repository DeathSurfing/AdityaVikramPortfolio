## A rewrite

Tailwind CSS v4 replaces the JavaScript configuration and the JavaScript build with a Rust engine that reads native CSS. The class names are mostly unchanged; the setup around them is not.

### CSS-first configuration

`tailwind.config.js` is gone. Configuration lives in CSS:

```css
@import "tailwindcss";

@theme {
  --color-primary: oklch(0.205 0 0);
  --color-brand: #ffcc00;
  --font-head: "Archivo Black", sans-serif;
  --shadow-md: 4px 4px 0 0 var(--color-border);
}
```

Tokens sit next to the styles that use them, so there is no second file to keep in sync.

### `@theme`

Custom values, fonts, shadows, and breakpoints all live in `@theme`:

```css
@theme {
  --font-sans: "Space Grotesk", sans-serif;
  --font-mono: "IBM Plex Mono", monospace;
  --color-muted: oklch(0.97 0 0);
  --breakpoint-xs: 480px;
}
```

## Syntax changes

### Arbitrary values

The bracket syntax keeps its form and runs faster:

```html
<!-- Before (v3) -->
<div class="top-[117px]">

<!-- After (v4): same syntax, new engine -->
<div class="top-[117px]">
```

### Variants

Most variants are unchanged. The ones that rely on configuration moved to `@custom-variant`:

| v3 | v4 | Notes |
|---|---|---|
| `first:` | `first:` | Unchanged |
| `focus-within:` | `focus-within:` | Unchanged |
| `group-hover:` | `group-hover:` | Unchanged |
| `motion-safe:` | `motion-safe:` | Unchanged |
| `dark:` | `dark:` | Uses `@custom-variant` |

### Custom variants

Define your own with `@custom-variant`:

```css
@custom-variant dark (&:is(.dark *));
@custom-variant portrait (@media (orientation: portrait));
@custom-variant open (&[open]);

/* Usage */
.card {
  background: white;
  @dark background: black;
  @portrait font-size: 14px;
}
```

## The engine

Tailwind v4 scans source files and generates CSS with a Rust engine called Oxide. Build times on the project sizes in the announcement:

| Project size | v3 | v4 | Speedup |
|---|---|---|---|
| Small (100 components) | 800ms | 50ms | 16x |
| Medium (500 components) | 3.2s | 180ms | 18x |
| Large (2000+ components) | 12s | 600ms | 20x |

## Migrating

### From v3

1. Move `tailwind.config.js` into `@theme` in CSS.
2. Update plugins to their v4-compatible versions.
3. Check that custom variants still resolve.
4. Run `npx @tailwindcss/upgrade` for the mechanical parts.

### Incrementally

A full migration is not required in one commit. The compatibility layer lets v4 and v3 coexist in the same project while routes are converted.

## Summary

The CSS-first configuration removes a build step's worth of setup, and the Rust engine makes the rebuild cost small enough that it stops shaping how you write styles. For a new project, v4 is the reasonable default.
