## What generics are

Generics let one implementation work with several types while keeping the type relationship between input and output. A type parameter is a placeholder that the caller fills in.

### The problem

Without generics you either duplicate the function or lose its type:

```typescript
// Type-safe but duplicated
function identityNumber(arg: number): number { return arg }
function identityString(arg: string): string { return arg }

// Flexible but unsafe
function identityAny(arg: any): any { return arg }
```

### The generic version

```typescript
function identity<T>(arg: T): T {
  return arg
}

const num = identity(42)        // Type: number
const str = identity("hello")   // Type: string
```

The return type follows the argument type, which neither `any` nor the duplicated pair can express.

## Practical patterns

### Constraints

`extends` limits which types a parameter accepts:

```typescript
interface HasLength {
  length: number
}

function logLength<T extends HasLength>(arg: T): T {
  console.log(arg.length)
  return arg
}

logLength("hello")     // string has length
logLength([1, 2, 3])   // arrays have length
logLength(42)          // compile error: number has no length
```

### Generic React components

```tsx
interface ListProps<T> {
  items: T[]
  renderItem: (item: T) => React.ReactNode
}

function List<T>({ items, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item, i) => (
        <li key={i}>{renderItem(item)}</li>
      ))}
    </ul>
  )
}
```

The component keeps the item type through `renderItem`, so a typo in the render function fails at the call site instead of at runtime.

### A key-value store

```typescript
class Store<T extends Record<string, unknown>> {
  private data: T

  constructor(initial: T) {
    this.data = initial
  }

  get<K extends keyof T>(key: K): T[K] {
    return this.data[key]
  }

  set<K extends keyof T>(key: K, value: T[K]): void {
    this.data[key] = value
  }
}
```

`get` returns the type of the specific key, so `store.get("count")` is a number and `store.set("count", "one")` does not compile.

## When to add one

- Utility functions that operate on several types
- Data structures such as stacks, queues, and trees
- Components that render different item types
- API wrappers where the response type varies

Start with the concrete version. Add a type parameter when a second caller needs the same logic with a different type, and add a constraint when the body needs a property the parameter does not guarantee.
